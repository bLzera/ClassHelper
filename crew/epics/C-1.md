# Épico C-1 — PATCH /assignments/:id/priority

## Spec do endpoint

```
PATCH /assignments/:id/priority
Auth: Bearer <jwt> obrigatório
Body: { "manual_priority": Integer }
Lógica: Assignment.find_by(id:, user: current_user) → atualiza manual_priority
Response 200: assignment atualizado (todos os campos)
Response 404: { "error": "not_found" }
Response 401: { "error": "unauthorized" } (sem token ou token inválido)
```

## Critérios de aceitação (specs obrigatórios)

1. `PATCH /assignments/:id/priority` com token válido e body `{ manual_priority: 1 }` → 200 com assignment atualizado
2. Assignment pertence a outro usuário → 404 (nunca expor que existe)
3. `id` inexistente → 404
4. Sem token → 401
5. Token inválido → 401

---

## Considerações especiais

- O response 200 deve incluir os campos: `id`, `title`, `manual_priority`, `auto_priority`, `due_date`, `state`, `course_id`
- `manual_priority` aceita qualquer Integer (incluindo nil para "limpar" a prioridade manual) — não validar range
- O método `update_priority` já existe como rota no `routes.rb` mapeando para `assignments#update_priority`
