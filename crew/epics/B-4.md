# Épico B-4 — Renovação de access_token via refresh_token

## Contexto

Quando o `access_token` do Google expira (tipicamente após 1 hora), as chamadas à API do Classroom retornam 401. Este épico implementa a renovação automática: ao detectar 401 na API Google, trocar o `refresh_token` por um novo `access_token` e repetir a requisição original.

Este épico não tem endpoint próprio — é uma camada de resiliência dentro dos services existentes.

---

## Spec do comportamento

```
Trigger: GoogleClassroomService ou qualquer chamada à API Google recebe HTTP 401
Lógica:
  1. Chamar GoogleOauthService#refresh_access_token(current_user.google_refresh_token)
     → POST https://oauth2.googleapis.com/token com grant_type=refresh_token
     → Retorna { access_token:, expires_in: }
  2. Atualizar current_user.google_access_token no banco
  3. Repetir a requisição original com o novo token
  4. Se o refresh também falhar (refresh_token inválido/revogado):
     → Limpar google_access_token e google_refresh_token do usuário
     → Retornar 401 com { "error": "token_expired", "message": "Re-autenticação necessária" }
```

## Critérios de aceitação (specs obrigatórios)

1. Token expirado (401 da API Google) → refresh automático → requisição original bem-sucedida → 200
2. Token expirado + refresh bem-sucedido → `user.google_access_token` atualizado no banco
3. Token expirado + refresh também falha (400 do endpoint de token Google) → tokens limpos no usuário → 401 com `token_expired`
4. `GoogleOauthService#refresh_access_token` com token válido → retorna novo access_token
5. `GoogleOauthService#refresh_access_token` com token inválido → raise `GoogleOauthService::RefreshError`

---

## Considerações especiais

- **Endpoint de refresh Google:** `POST https://oauth2.googleapis.com/token` com body:
  ```
  client_id=<GOOGLE_CLIENT_ID>
  client_secret=<GOOGLE_CLIENT_SECRET>
  refresh_token=<refresh_token>
  grant_type=refresh_token
  ```
- **Retry é feito uma única vez.** Se o refresh falhar, não tentar de novo.
- **Implementar o retry no service, não no controller.** Os controllers não devem saber que houve um refresh.
- **Thread safety:** `user.update!` é suficiente, sem necessidade de locks otimistas para este caso.
- **`google_refresh_token` nil:** alguns usuários podem não ter refresh_token (se fizeram login sem `access_type=offline`). Nesse caso, ir direto para a resposta 401 `token_expired` sem tentar o refresh.
