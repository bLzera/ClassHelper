# Épico F-10 — Toggle pendentes/concluídas

> **Épico de FRONTEND.** Gate = `run-fe-tests.sh` + `run-fe-lint.sh`. Depende de **F-9** e **B-9** (e B-8 p/ os dados).

## Objetivo

Adicionar um **toggle simples** "mostrar concluídas" na visão global ("Todas as tarefas") e na tela
de curso. Concluída = **`TURNED_IN`**. Pendente (default) = **`CREATED`**.

## Contrato da API consumida

```
GET /dashboard?completed=<bool>                 (Bearer) → { assignments: [...] }
GET /courses/:id/assignments?completed=<bool>   (Bearer) → { assignments: [...] }
  completed=false (default) → pendentes (CREATED); completed=true → concluídas (TURNED_IN)
```

## Critérios de aceitação (specs obrigatórios)

1. Há um toggle "mostrar concluídas" na visão "Todas as tarefas" e na tela de curso
2. Por padrão o toggle está **desligado** → lista pendentes (`completed=false`)
3. Ligar o toggle refaz a busca com `completed=true` e mostra só as concluídas (`TURNED_IN`)
4. Alternar o toggle dispara a busca correspondente (mockar a api) e atualiza a lista
5. Estado vazio específico quando não há concluídas ("nenhuma tarefa concluída")
6. Store `assignments`: `fetchDashboard(completed?)` passa o param e atualiza a lista

---

## Considerações especiais

- Toggle simples de **2 estados** apenas (sem multi-filtro) — decisão de produto: não haverá mais
  filtros tão cedo.
- O `StateToggle` deve ser genérico (emite o estado/valor) e ser reusado nas duas telas.
- Concluídas vêm ordenadas por `due_date DESC` do backend (B-9); o front só renderiza na ordem recebida.
- O editor de prioridade (F-6) faz sentido só para pendentes; em concluídas pode ficar oculto/inativo
  (decisão de implementação — documentar no output).
