# Épico B-9 — Filtro de estado nas listagens + GET /assignments/:id

> Depende de **B-8** (estado de submissão já sincronizado, pra "concluídas" ter sentido).

## Objetivo

Dar ao frontend (F-9, F-10, F-11) os endpoints de leitura que faltam:
1. filtro pendentes/concluídas no dashboard global e na listagem por curso;
2. endpoint de detalhe de um assignment (rota `/assignments/:id` com URL compartilhável).

## Specs dos endpoints

```
GET /dashboard?completed=<true|false>      (Bearer)
  - completed ausente ou false → assignments com state == "CREATED" (pendentes), ordem atual
    (COALESCE(manual_priority, auto_priority) ASC NULLS LAST)
  - completed=true → assignments com state == "TURNED_IN", ordenados por due_date DESC NULLS LAST
  Response 200: { "assignments": [ ... ] }   (mesmos campos de hoje + alternate_link)

GET /courses/:id/assignments?completed=<true|false>   (Bearer)
  - assignments do curso :id pertencente ao current_user
  - mesma semântica de filtro/ordenação do dashboard
  Response 200: { "assignments": [ ... ] }
  Response 404: { "error": "not_found" }   (curso inexistente ou de outro usuário)

GET /assignments/:id                         (Bearer)
  - um assignment do current_user, com todos os campos do detalhe + nome do curso + alternate_link
  Response 200: { "assignment": { id, title, description, due_date, state,
                  manual_priority, auto_priority, alternate_link, course_id, course_name } }
  Response 404: { "error": "not_found" }
```

## Critérios de aceitação (specs obrigatórios)

1. `GET /dashboard` (sem param ou `completed=false`) → só `CREATED`, ordem por prioridade efetiva
2. `GET /dashboard?completed=true` → só `TURNED_IN`, ordenados por `due_date DESC NULLS LAST`
3. `GET /courses/:id/assignments` aplica o mesmo filtro, restrito ao curso e ao usuário
4. `GET /courses/:id/assignments` com curso de outro usuário ou inexistente → 404
5. `GET /assignments/:id` retorna o detalhe completo incl. `course_name` e `alternate_link`
6. `GET /assignments/:id` com id inexistente ou de outro usuário → 404
7. Todos exigem token (401 sem JWT)

---

## Considerações especiais

- "Concluídas" = **apenas `TURNED_IN`** (decisão do produto). `RETURNED`/`RECLAIMED_BY_STUDENT` não
  entram nem em pendentes nem em concluídas por ora — manter o filtro simples (toggle de 2 estados).
- O serializer de detalhe inclui `course_name` (join com `courses.name`), os demais campos espelham
  o dashboard + `alternate_link` (de B-7).
- Evitar N+1 no `course_name` (usar `includes(:course)` ou select com join).
- Reaproveitar a ordenação por prioridade efetiva já existente no `dashboard_controller`.
