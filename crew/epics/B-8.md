# Épico B-8 — Sync do estado de submissão (studentSubmissions)

## Objetivo

Hoje o sync grava em `assignment.state` o estado de **publicação do professor** (`courseWork.state`:
PUBLISHED/DRAFT/DELETED), então toda tarefa acaba como `CREATED`. O estado de **entrega do aluno**
(`TURNED_IN`, `RETURNED`, `RECLAIMED_BY_STUDENT`) vive em outro recurso da API do Google:
`studentSubmissions`. Este épico passa a buscar esse recurso e gravar o estado real, viabilizando o
filtro "concluídas" (B-9 / F-10).

## Contrato da API consumida (Google)

```
GET https://classroom.googleapis.com/v1/courses/{courseId}/courseWork/-/studentSubmissions?userId=me
  Authorization: Bearer <access_token do usuário>
  ("-" como courseWorkId retorna as submissões de TODAS as tarefas do curso numa só chamada)
Response: { "studentSubmissions": [ { "id", "courseWorkId", "state", ... } ] }
  state ∈ { SUBMISSION_STATE_UNSPECIFIED, NEW, CREATED, TURNED_IN, RETURNED, RECLAIMED_BY_STUDENT }
```

## Mapeamento de estado

```
NEW, CREATED, SUBMISSION_STATE_UNSPECIFIED   → "CREATED"   (pendente)
TURNED_IN                                    → "TURNED_IN"
RETURNED                                     → "RETURNED"
RECLAIMED_BY_STUDENT                         → "RECLAIMED_BY_STUDENT"
(VALID_STATES já cobre esses 4 valores no model)
```

## Critérios de aceitação (specs obrigatórios)

1. `GoogleClassroomService#fetch_submissions(course_id)` faz GET no endpoint de studentSubmissions
   (com `userId=me`) reusando o `with_token_refresh` existente; retorna `[]` quando não há `studentSubmissions`
2. Durante o `POST /assignments/sync`, para cada curso, as submissões são buscadas e o `state` de cada
   assignment é atualizado conforme o `courseWorkId` correspondente
3. Submissão `TURNED_IN` → assignment fica com `state == "TURNED_IN"`
4. Submissão `NEW`/`CREATED` → assignment permanece `"CREATED"`
5. Assignment sem submissão correspondente permanece `"CREATED"` (default)
6. Falha na API de submissões (status != 200) → mesmo tratamento dos demais erros do sync
   (`502 classroom_api_error`)

---

## Considerações especiais

- A chamada de submissões fica **fora da transaction** de upsert (mesma razão do `fetch_course_work`:
  um refresh malsucedido limpa tokens e não pode ser desfeito por rollback).
- Casar submissão→assignment pelo `courseWorkId` (== `google_assignment_id` do assignment).
- O `map_state` atual (baseado em `courseWork.state`) deixa de definir o estado final — o estado de
  submissão tem a palavra final. Tarefa criada sem submissão fica `CREATED`.
- Uma chamada de submissões **por curso** (usando o wildcard `-`), não por tarefa, pra economizar quota.
