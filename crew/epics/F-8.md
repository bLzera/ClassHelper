# Épico F-8 — Auto-sync no login + "Sincronizar agora"

> **Épico de FRONTEND.** Gate = `run-fe-tests.sh` + `run-fe-lint.sh`. Depende de **F-7** e **B-10**.

## Objetivo

Disparar a sincronização automaticamente toda vez que o app abre autenticado (o **throttle de 1h**
é tratado no backend — F-8 só chama `POST /sync`), com carregamento via `<Suspense>` no primeiro
acesso e atualização em background quando já há dados. Ligar o botão **"Sincronizar agora"** (força,
`?force=true`) e o indicador **"última sincronização: há X min"** no shell (de F-7).

## Contrato da API consumida

```
POST /sync            (Bearer) → 200 { skipped, synced_courses?, synced_assignments?, last_synced_at }
POST /sync?force=true (Bearer) → idem, ignorando o throttle
GET  /auth/me         (Bearer) → { ..., last_synced_at }   (pro indicador carregar na entrada)
```

## Critérios de aceitação (specs obrigatórios)

1. Ao montar o shell autenticado, o app chama `POST /sync` **uma vez** (sem `force`); o throttle de 1h
   é responsabilidade do backend (o front não decide pular)
2. **Primeiro acesso (sem dados):** enquanto o sync inicial não termina, a UI mostra estado de
   carregamento (`<Suspense>`/fallback); ao terminar, carrega o conteúdo
3. **Acessos seguintes (já há dados):** mostra os dados que já temos e atualiza em background (não
   bloqueia a tela)
4. Se o sync não retornar nenhum curso/tarefa, exibe mensagem "nenhum curso pra sincronizar"
5. O botão **"Sincronizar agora"** chama `POST /sync?force=true`, mostra loading, e ao terminar
   atualiza a lista visível e o indicador de última sync
6. O indicador "última sincronização" mostra o tempo relativo a partir de `last_synced_at`
7. Store `sync`: `syncNow(force?)` gerencia `loading`/`error` e devolve o resultado

## Considerações especiais

- **Refatoração do store de sync (F-5):** os três botões/ações antigos (cursos/tarefas/tudo) dão lugar
  a um `syncNow(force?)` único batendo em `POST /sync`. Ajustar os testes de F-5 que dependiam disso.
- O refresh pós-sync reusa os stores de listagem (`assignments.fetchDashboard`, e os de F-9) — não
  duplicar fetch.
- `<Suspense>`: usar o componente do Vue 3 envolvendo o conteúdo cujo `setup`/load assíncrono depende
  do sync/fetch inicial. Documentar a estratégia (suspense vs flag de loading) no output.
- Tempo relativo ("há X min") pode ser simples (cálculo próprio com `Intl.RelativeTimeFormat` ou
  string manual); não adicionar dependência nova.
- Evitar disparo duplo do auto-sync (ex: guard de "já disparou nesta montagem").
