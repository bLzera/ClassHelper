# Épico B-6 — GET /courses (listagem com agregados)

## Spec do endpoint

```
GET /courses
Auth: Bearer <jwt> obrigatório
Lógica: lista os cursos do current_user, cada um com agregados de tarefas pendentes:
  - pending_count: nº de assignments do curso com state == "CREATED"
  - next_due_date: menor due_date (ISO8601) entre os assignments pendentes (CREATED)
    com due_date não-nulo; null se não houver
Response 200: {
  "courses": [
    { "id": UUID, "google_course_id": String, "name": String, "section": String|null,
      "pending_count": Integer, "next_due_date": ISO8601|null }
  ]
}
Response 401: { "error": "unauthorized" } (sem token JWT)
```

## Critérios de aceitação (specs obrigatórios)

1. `GET /courses` com token válido → 200 com a lista de cursos do usuário
2. Cada curso traz `pending_count` = nº de assignments com `state == "CREATED"`
3. `next_due_date` = menor `due_date` entre os pendentes; `null` quando não há pendente com prazo
4. Cursos sem assignments retornam `pending_count: 0` e `next_due_date: null`
5. Só retorna cursos do `current_user` (isolamento por usuário)
6. Sem token → 401

---

## Considerações especiais

- **Evitar N+1:** computar os agregados com uma única query (ex: `left_joins(:assignments)` +
  `group` + `select` com `COUNT`/`MIN` filtrados por `state = 'CREATED'`), não iterar curso a curso
  disparando query por curso. Documentar a abordagem no output.
- `next_due_date` considera **apenas** assignments pendentes (`CREATED`) e com `due_date` presente.
- Ordenação da lista de cursos: por `name` ascendente (estável e previsível).
