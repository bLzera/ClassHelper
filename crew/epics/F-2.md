# Épico F-2 — Scaffold & infra do frontend

> **Épico de FRONTEND.** A stack e o gate de qualidade são diferentes dos épicos de backend.
> O fluxo do crew (`run-tests.sh`/`run-lint.sh`/prompt do developer) é 100% Ruby; este épico também
> **adapta o crew** para o frontend (ver "Considerações especiais").

## Objetivo

Criar o projeto frontend do zero em `frontend/`, com toda a infraestrutura que os épicos F-3..F-6 vão
consumir: build, roteamento, store, cliente HTTP autenticado, estilo e testes. Sem telas de produto
ainda (isso é F-3+) — apenas o esqueleto navegável e o ferramental.

## Stack (decidida)

```
Vue 3 + Vite + TypeScript
Pinia (state)        Vue Router (rotas)
Tailwind CSS         ESLint + Prettier
Vitest + Vue Test Utils (testes)
axios (cliente HTTP)
```

## Critérios de aceitação

1. `cd frontend && npm install && npm run build` completa sem erros (build de produção do Vite)
2. `npm run dev` sobe o Vite na porta `5173` e a rota `/` renderiza o `HomeView` placeholder
3. `npm run lint` (ESLint) e `npm run type-check` (`vue-tsc --noEmit`) passam sem erros
4. `npm run test` (Vitest) roda e passa um smoke test (ex: monta `App.vue` e asserir que renderiza)
5. `src/lib/api.ts` exporta uma instância axios com `baseURL` lido de `import.meta.env.VITE_API_BASE_URL`
   e um interceptor de request que injeta `Authorization: Bearer <token>` quando há token no localStorage
6. `.env.example` documenta `VITE_API_BASE_URL`; `frontend/.gitignore` ignora `node_modules`, `dist`, `.env`
7. `crew/run-fe-tests.sh` e `crew/run-fe-lint.sh` existem, são executáveis e têm a mesma lógica de
   detecção host-vs-container do `run-tests.sh` (ou rodam no host se Node estiver disponível)

## Considerações especiais

- **Token storage:** o interceptor lê o JWT de `localStorage` (chave `classhelper_token`). A escrita
  do token é responsabilidade do F-3 — aqui só preparamos a leitura.
- **CORS:** o backend já libera `http://localhost:5173` (`CORS_ORIGINS`) com `credentials: false`.
  Como usamos Bearer no header (não cookie), não precisa de `withCredentials`.
- **Adaptação do crew (obrigatória neste épico):** os épicos F-* não passam pelo `bundle exec rspec`.
  Criar `run-fe-tests.sh` (gate = `vitest run`) e `run-fe-lint.sh` (gate = `vue-tsc --noEmit` + `eslint`,
  escopado aos arquivos que o épico tocou via diff `main...HEAD`, espelhando o `run-lint.sh`). Adicionar
  ao `orchestrator.md` uma seção curta dizendo que, para épicos `F-*`, os Passos 3 e 4 usam esses
  scripts e o Developer Agent recebe um prompt de frontend (Vue/TS) em vez do prompt Rails.
- **Sem lógica de produto:** nada de login, dashboard ou chamadas reais à API aqui — só o esqueleto.
- **Node:** assumir Node LTS (20+). Versionar via `package.json` `engines` se conveniente.
