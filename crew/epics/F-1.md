# Épico F-1 — GET /dashboard

## Spec do endpoint

```
GET /dashboard
Auth: Bearer <jwt> obrigatório
Lógica: current_user.assignments
          .where(state: "CREATED")
          .order(Arel.sql("COALESCE(manual_priority, auto_priority) ASC NULLS LAST"))
Response 200: { "assignments": Array<assignment> }
Response 401: { "error": "unauthorized" }
```

## Critérios de aceitação (specs obrigatórios)

1. `GET /dashboard` com token válido e assignments no estado `CREATED` → 200 com lista ordenada por prioridade efetiva
2. Assignments no estado `TURNED_IN`, `RETURNED`, `RECLAIMED_BY_STUDENT` **não** aparecem no dashboard
3. Prioridade efetiva: `manual_priority` tem precedência sobre `auto_priority`; sem nenhuma → aparecem por último (NULLS LAST)
4. Sem token → 401
5. Token inválido → 401
6. Usuário sem assignments → 200 com `{ "assignments": [] }`

## Considerações especiais

- **Ordenação:** `COALESCE(manual_priority, auto_priority) ASC NULLS LAST` — menor número = maior prioridade
- **Campos do assignment no response:** `id`, `title`, `description`, `due_date`, `state`, `manual_priority`, `auto_priority`, `course_id`
- Se precisar incluir o nome do curso no response, fazer com `.includes(:course)` e adicionar `course_name` no JSON — mas só se necessário para o frontend; por ora, `course_id` é suficiente
- As factories de course e assignment provavelmente não existem ainda — o Developer deve criá-las
