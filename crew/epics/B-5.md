# Épico B-5 — Callback OAuth redireciona pro frontend com token

## Contexto

Hoje `GET /auth/callback` é chamado pelo Google e responde **JSON** (`{ access_token, token_type }`)
diretamente no browser. Um SPA não consegue ler esse JSON — o browser só renderiza a página.
Este épico muda o callback para **redirecionar** o browser de volta ao frontend, levando o JWT no
**fragment** da URL (`#token=...`), que o SPA lê no client (épico F-3). Em caso de erro, redireciona
com `#error=...`.

Mantém o modelo de auth stateless/Bearer atual (`authenticate_user!` continua lendo
`Authorization: Bearer`). A única mudança de contrato é: o callback deixa de responder JSON e passa
a responder `302`.

## Spec do endpoint

```
GET /auth/callback
Auth: nenhuma
Query params: code (obrigatório no sucesso), error (indica falha OAuth do Google)

Env nova: FRONTEND_URL (default "http://localhost:5173")

Lógica (sucesso):
  1. troca code por tokens (GoogleOauthService#exchange_code)
  2. busca userinfo (fetch_userinfo)
  3. upsert do User por google_id (preserva refresh_token quando o Google não reenvia)
  4. emite JWT próprio (JwtService.create_access_token, user_id no payload)
  5. redirect 302 → "#{FRONTEND_URL}/auth/callback#token=<jwt>"

Lógica (params[:error] presente):
  redirect 302 → "#{FRONTEND_URL}/auth/callback#error=oauth_error"
  (NÃO troca o code)

Lógica (exceção em qualquer passo):
  redirect 302 → "#{FRONTEND_URL}/auth/callback#error=auth_failed"

Response: 302 em todos os casos. O token/erro vai SEMPRE no fragment (#), nunca na query string,
para não vazar em logs de servidor/access logs.
```

## Critérios de aceitação (specs obrigatórios)

1. Callback com `code` válido → `302`, com `Location` = `<FRONTEND_URL>/auth/callback#token=<jwt>`;
   o JWT no fragment decodifica para o `user_id` do usuário criado/atualizado
2. Upsert: callback com `google_id` novo **cria** o User; com `google_id` existente **atualiza**
   (email/name/access_token) sem duplicar
3. `refresh_token` é preservado quando o Google **não** reenvia um novo no `exchange_code`
4. Callback com `params[:error]` presente → `302` com `Location` contendo `#error=oauth_error`,
   e **não** chama `exchange_code` (verificar que o WebMock do token endpoint não foi atingido)
5. Exceção em `exchange_code` ou `fetch_userinfo` → `302` com `Location` contendo `#error=auth_failed`
6. O token/erro nunca aparece na query string do `Location` (sempre depois do `#`)

## Considerações especiais

- **`redirect_to ... , allow_other_host: true`** — o frontend é outro host/porta (`:5173` ≠ `:3000`),
  então o redirect precisa de `allow_other_host: true` senão o Rails 7 bloqueia.
- **Fragment no `Location`:** montar a URL como string e passar pro `redirect_to`. Em request spec,
  asserir com `response.location` (deve incluir `#token=` / `#error=`).
- **`FRONTEND_URL`:** ler com `ENV.fetch("FRONTEND_URL", "http://localhost:5173")`. Não confundir com
  `GOOGLE_REDIRECT_URI` (essa continua apontando pro backend `:3000/auth/callback`, é a URI registrada
  no Google Cloud Console e não muda).
- **Não** alterar `GoogleOauthService` nem o `authorize_url`/scopes — só o controller.
- O endpoint `/auth/me` e o `login` ficam intactos.
