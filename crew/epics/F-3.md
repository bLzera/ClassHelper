# Épico F-3 — Fluxo de autenticação (frontend)

> **Épico de FRONTEND.** Gate = `run-fe-tests.sh` + `run-fe-lint.sh` (ver F-2). Depende de **F-2** e **B-5**.

## Objetivo

Implementar o login Google ponta a ponta no SPA: iniciar o fluxo, receber o JWT do redirect do backend
(`#token=...`, conforme B-5), persistir, buscar o usuário (`/auth/me`), proteger rotas e permitir logout.

## Fluxo

```
1. Usuário clica "Entrar com Google" → window.location.href = `${VITE_API_BASE_URL}/auth/login`
2. Backend → Google → backend /auth/callback → 302 para `${frontend}/auth/callback#token=<jwt>`  (B-5)
3. Rota /auth/callback (CallbackView):
   - lê location.hash; se #token → authStore.setToken(token); limpa o hash; fetch /auth/me; vai pra /dashboard
   - se #error=<msg> → mostra erro e redireciona pra /login
4. Route guard: rotas protegidas exigem token; sem token → redirect /login
5. Logout: authStore.logout() limpa token + user e vai pra /login
```

## Contrato da API consumida

```
GET /auth/me   →  200 { id, email, name, created_at }   |  401 { error: "unauthorized" }
```

## Critérios de aceitação (specs obrigatórios)

1. `authStore.setToken(t)` persiste o token em `localStorage` (chave `classhelper_token`) e marca
   `isAuthenticated === true`
2. `authStore.logout()` limpa token + user do estado e do `localStorage`, e `isAuthenticated === false`
3. `authStore.fetchMe()` chama `GET /auth/me` e popula `user` (mockar o axios/api)
4. `CallbackView`, com `#token=<jwt>` no hash, chama `setToken` e redireciona pra `/dashboard`
5. `CallbackView`, com `#error=<msg>` no hash, **não** seta token e redireciona pra `/login`
6. Guard: navegar pra rota protegida **sem** token redireciona pra `/login`; **com** token, permite
7. Interceptor de response: um `401` da API dispara `logout()` (sessão expirada → volta pro login)

## Considerações especiais

- **Limpar o hash** após ler o token (`history.replaceState`) pra não deixar o JWT na barra de endereço.
- O guard deve permitir `/login` e `/auth/callback` sem token (rotas públicas).
- Testes de componente com Vue Test Utils + Vitest; mockar `api`/axios e o router conforme necessário.
- Não criar a tela de dashboard aqui — apenas a navegação até a rota `/dashboard` (que pode ser o
  placeholder de F-2 até o F-4 implementar).
