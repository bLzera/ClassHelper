# Épico F-11 — Tela de detalhe do assignment + link "Abrir no Classroom"

> **Épico de FRONTEND.** Gate = `run-fe-tests.sh` + `run-fe-lint.sh`. Depende de **F-7**, **B-7** e **B-9**.

## Objetivo

Rota própria **`/assignments/:id`** com o detalhe da tarefa (URL compartilhável), incluindo um botão
**"Abrir no Classroom"** que leva à tarefa no Google Classroom (onde a entrega de fato acontece). Os
cards passam a linkar para essa tela.

## Contrato da API consumida

```
GET /assignments/:id   (Bearer) → { assignment: { id, title, description, due_date, state,
                        manual_priority, auto_priority, alternate_link, course_id, course_name } }
                       404 → { error: "not_found" }
```

## Critérios de aceitação (specs obrigatórios)

1. `/assignments/:id` busca e mostra: título, descrição completa, prazo, estado, prioridade efetiva,
   nome do curso, e o **editor de prioridade manual** (reusa F-6, atualiza via `PATCH`)
2. Há um botão/link **"Abrir no Classroom"** apontando para `alternate_link`, abrindo em nova aba
   (`target="_blank"` + `rel="noopener noreferrer"`)
3. Quando `alternate_link` é `null` (dado antigo não re-sincronizado), o botão **não** aparece
4. `404` da API → feedback "tarefa não encontrada" sem quebrar a tela
5. Os `AssignmentCard` (dashboard e tela de curso) linkam para `/assignments/:id`
6. Estados de loading/erro tratados; ao editar a prioridade no detalhe, o valor reflete na tela
7. Store `assignments`: `fetchAssignment(id)` busca o detalhe e trata erro

---

## Considerações especiais

- O detalhe é uma rota **dentro do shell** (sidebar continua visível).
- Reusar `PriorityEditor` (F-6) e a action `updatePriority` (F-6) — não duplicar lógica de PATCH.
- O link do card não deve "engolir" o clique do editor de prioridade embutido (cuidado com a área
  clicável: linkar o título/área dedicada, não o card inteiro por cima dos controles).
- Tailwind; layout de detalhe simples e legível (não precisa de muitos dados, conforme o escopo).
