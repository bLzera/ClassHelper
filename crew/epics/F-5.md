# Épico F-5 — Ações de sync (frontend)

> **Épico de FRONTEND.** Gate = `run-fe-tests.sh` + `run-fe-lint.sh` (ver F-2). Depende de **F-4**.

## Objetivo

Permitir que o usuário dispare a sincronização com o Google Classroom a partir do dashboard:
sincronizar cursos e sincronizar tarefas, com feedback de progresso/erro e atualização da lista.

## Contrato da API consumida

```
POST /courses/sync      (Bearer)  →  200 { synced: Integer, courses: Array }
POST /assignments/sync  (Bearer)  →  200 { synced: Integer }

Fluxo recomendado: sync de cursos primeiro, depois sync de tarefas (tarefas dependem dos cursos),
em seguida refazer o GET /dashboard para refletir as novidades.
```

## Critérios de aceitação (specs obrigatórios)

1. Há um controle para "Sincronizar cursos" que chama `POST /courses/sync` e outro para
   "Sincronizar tarefas" que chama `POST /assignments/sync` (mockar o axios/api)
2. Enquanto a request está em andamento, o botão exibe estado de **loading** e fica desabilitado
   (sem disparo duplo)
3. Em **sucesso**, a lista do dashboard é atualizada (chama `fetchDashboard` novamente) e há feedback
   de sucesso (ex: "N sincronizados")
4. Em **erro** (request falha), exibe feedback de erro e **não** quebra a tela; o botão volta ao estado
   idle
5. Store `sync`: `syncCourses()` e `syncAssignments()` alternam `loading`/`error`/`lastResult`
   corretamente

---

## Considerações especiais

- Evitar disparo duplo (debounce/disabled durante loading).
- O refresh pós-sync reusa o store de F-4 (`assignments.fetchDashboard`) — não duplicar a lógica de fetch.
- Decidir na implementação se "sincronizar tudo" encadeia cursos→tarefas num clique ou se são dois
  botões separados; documentar a escolha no output. Default sugerido: dois botões + um "sincronizar tudo"
  opcional que encadeia.
- Tailwind; manter `SyncButton` genérico (recebe label + action via props).
